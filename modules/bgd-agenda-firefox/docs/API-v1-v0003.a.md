# BrasilGuard Agenda — API v1 — v0003.a

## Objetivo
Contrato inicial para clientes da plataforma (extensões, web/PWA, integrações e N8N). REST é prioridade na v1; GraphQL fica fora do MVP.

## Convenções
- base lógica: `/api/v1`;
- tenant explícito por rota ou contexto autenticado;
- timestamps em ISO-8601/UTC;
- timezone em identificador IANA;
- operações críticas aceitam/exigem `Idempotency-Key`;
- respostas de erro têm `error` estável e status HTTP coerente.

## Público
### GET `/public/{tenantSlug}/bootstrap`
Retorna somente configuração pública:
- tenant;
- branding;
- serviços ativos;
- profissionais ativos.

Nunca retorna dados pessoais de clientes/agendamentos.

### GET `/public/{tenantSlug}/schedule`
Query:
- `date=YYYY-MM-DD`
- `professional_id` opcional
- `service_id` opcional
- `duration` quando necessário

Resposta expõe apenas blocos:
```json
{
  "startsAt": "2026-09-04T12:00:00Z",
  "status": "free",
  "label": "LIVRE"
}
```
ou `busy`/`OCUPADO`.

## Autenticado
### GET `/tenants/{tenantId}/me`
Retorna membership, papel e permissões no tenant.

### Clientes
- `POST /tenants/{tenantId}/clients`
- `GET /tenants/{tenantId}/clients/{id}`
- `PATCH /tenants/{tenantId}/clients/{id}`

Cadastro mínimo para agendamento online:
- nome válido;
- e-mail válido/verificado;
- telefone válido.

### Profissionais
- `GET /tenants/{tenantId}/professionals`
- `POST /tenants/{tenantId}/professionals`
- `PATCH /tenants/{tenantId}/professionals/{id}`

### Serviços
- `GET /tenants/{tenantId}/services`
- `POST /tenants/{tenantId}/services`
- `PATCH /tenants/{tenantId}/services/{id}`

### Agendamentos
- `POST /tenants/{tenantId}/appointments`
- `GET /tenants/{tenantId}/appointments/{id}`
- `PATCH /tenants/{tenantId}/appointments/{id}`
- `POST /tenants/{tenantId}/appointments/{id}/reschedule`
- `POST /tenants/{tenantId}/appointments/{id}/cancel`

O servidor deve revalidar disponibilidade imediatamente antes de persistir.

## Webhooks / N8N
### `POST /tenants/{tenantId}/webhooks`
Configura endpoint e eventos assinados.

Eventos iniciais:
- `appointment.created`
- `appointment.updated`
- `appointment.rescheduled`
- `appointment.cancelled`
- `appointment.completed`
- `appointment.no_show`
- `payment.created`
- `payment.approved`
- `payment.failed`
- `payment.refunded`

Entrega prevista:
- HMAC;
- retry exponencial;
- dead-letter;
- `X-BGD-Event`;
- `X-BGD-Delivery`;
- `X-BGD-Signature`.

## Pagamentos
### `POST /tenants/{tenantId}/payments`
Obrigatório:
```http
Idempotency-Key: <uuid-ou-chave-estável>
```

Payload desacoplado do provider:
```json
{
  "appointmentId": "uuid",
  "provider": "stripe|mercadopago|infinitypay|pix|...",
  "amount": 50.00,
  "currency": "BRL",
  "metadata": {}
}
```

## Analytics
### `POST /tenants/{tenantId}/analytics`
Eventos de funil e performance sem incluir PII desnecessária.

## Offline-first
Mutação local recebe chave idempotente e estado de sincronização. O servidor pode responder conflito de disponibilidade; o cliente deve marcar `conflict` e solicitar novo slot em vez de sobrescrever a agenda.

## Outlook/Microsoft
A integração será implementada pela camada `calendar_connections`, usando Microsoft Graph e cursor incremental. O contrato do core não deve depender de um provider específico.
